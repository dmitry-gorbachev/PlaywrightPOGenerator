1. **Implement module** (e.g., HTML parser)
2. **Run tests** — confirm all related tests pass
3. **Regression check** — re-run full suite (all 97)
4. **Commit** only when full suite is green

## Notes for Implementation

1. **Determinism is critical** — Tests verify identical output for same input. Use sorted keys, stable iteration.

2. **Cheerio** for parsing (CSS selectors + `.attr()` / `.text()`) — it's what the test harness uses.

3. **Locator strategy selection** must follow the order in the spec exactly. No shortcuts.

4. **Class naming** priority: derived from `<title>`, `data-testid`, `data-qa`, `id`, or type-based index. Implement consistent camelCase to PascalCase conversion.

5. **Method naming** follows verb+object pattern: `click*()`, `fill*()`, `is*Visible()`, `get*Text()`.

6. **Test-first discipline** — Add edge case fixture + expected output to fixtures.ts BEFORE writing implementation.
